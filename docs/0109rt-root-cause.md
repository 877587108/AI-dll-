## 一、对齐验证（用户要求：测之前先确认图对齐了）

工具：`markloc_aligncheck`。它做三件事互证：
全局相位相关量、逐字符 `matchTemplate` 残差、模型与图像的归一化相关系数。

| 项 | 0109_RT | 0109_FT |
| --- | --- | --- |
| 全局相位相关 | dx=-17.73 dy=-7.93 | dx=-2.36 dy=-9.53 |
| 对齐后吻合度 | 0.2238 → **0.6220** | 0.4571 → **0.7907** |
| \|dy\| 中位（对齐后） | 8 → **1** | 9 → **1** |
| \|dx\| 中位（对齐后） | 10 → **9** | 2 → **0** |
| 残差 >3px 的字符 | **16/22** | 6/22 |

**结论：图是对齐的。** 全局平移把吻合度从 0.22 提到 0.62，方向正确；
y 方向残差降到 1px，等于已对齐。x 方向 0109_RT 有 9px 残留，是真实现象。

**但这个残留不是误报的原因**——见下面的负结果。

### 过程中的一个工具 bug（记录下来防止复发）

`markloc_aligncheck` 第一版写的是 `cv::Mat sigAl = sigRaw;`（浅拷贝），
然后 `warpAffine(sigRaw, sigAl, ...)`。源与目标是同一块内存，行为未定义，
**实测一个像素都不改**。表现是所有对齐指标恒定不变到小数点后四位。

生产代码 `batchcore.hpp` 用的是独立的 `align` 变量，没有这个问题。
教训：**一个恒定的指标必须先自证它能变**，否则后面所有判读都是空的。
现在工具里加了 `[3a 自检]`，打印 warp 前后差值，差值必须 > 1e-6。

## 四、仍然站得住的观察

**唯一没被推翻的分界：笔画方向一致度。**
沿线取亮像素，取模型墨迹局部梯度（笔画法向）的垂直方向为笔画切向，
算线段方向与笔画的 |cos|。

| | 平行中位 | 横穿占比 |
| --- | --- | --- |
| 真缺陷 0026_FT / 0026_RT | 0.595 / 0.601 | 0.08 / 0.08 |
| 真缺陷 0083_FT / 0083_RT | 0.542 / 0.566 | 0.19 / 0.16 |
| 真缺陷 0112_FT / 0112_RT | 0.673 / 0.648 | 0.37 / 0.37 |
| **0109_RT** | **0.905** | **0.00** |

0109_RT 最严重那条完全平行于笔画，一次都没横穿。这个量有区分力，
但接进判定后只把 0109_RT 从"确定"压到"明显"，没压到门槛以下——
因为剩下的几条是短线，方向采样不足（64~173px 只能取到 3~7 个有效样本）。
已改为 2px 步长 + ±2px 垂直邻域扩样，仍不足以把这批短竖线判掉。

## 五、下一步该做什么

1. **先解决短线的方向测不准问题**（工程问题，不是判据问题）。
   短竖线本身和字形竖笔方向一致，用"方向一致度"天然分不开——
   需要引入"这条线的两个端点是否都落在字形墨迹之内"之类的判据。
2. 不要再碰跨越字数（已证明一动真缺陷先死）。
3. 不要再碰像素重对齐（已证明更糟）。
4. 字符框切分错误（宽 16/21/279 三个异常框，见 out/boxaudit.txt）
   属于建模层问题，应当在重做切分时一起解决，不要在判定层打补丁。
