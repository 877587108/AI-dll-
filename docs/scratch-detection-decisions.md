## 一、缺陷定义（已确认）

| 项 | 定义 |
| --- | --- |
| 缺陷类型 | **只有一种**：划痕，且影响字符识别 |
| 字符框内 | 无论深浅都算 |
| 字符框外 | 判「不影响识别」，放行 |
| 检测范围 | 字符框并集 + 固定外扩（`growPx`） |
| 跨字数 | 跨越字数越多越严重，**加权** |
| 分级 | 4 档：轻微 / 可疑 / 明显 / 确定，**不打数值分** |
| 图上标注 | 必须 |

## 二、判定链路（当前实现）

```
strokeSignal (CV_32F, 值域实测 0 ~ 1.8，未归一化)
  → cv::phaseCorrelate 全局对齐（字符并集 + 20px 窗口）
  → 逐字符 matchTemplate TM_CCOEFF_NORMED 精对齐（±12px，mVal < 0.30 拒）
  → findScratches:
      weak   = S > missStrokeLo * 0.7        (= 0.105)
      modelInk = freq > blankFreq * 255      (= 38)
      modelInk dilate {9,9} 椭圆核
      weak  AND  NOT(modelInk)  → 划痕候选
      CLOSE(bridge=25) → medianBlur(3) → HoughLinesP
  → composite = depth × charsHit
  → 4 档分级（cutCertain=1900 / cutObvious=1300 / cutSuspect=1000）
```

### 3.2 信号亮度分位数（**84 张 ok 全量，仅 v00 视角**）

统计区域 = 22 个字符框并集，不用全图（管脚/治具反光会污染分位数）。

| 分位 | 最小值 | p10 | 中位数 | p90 | 最大值 |
| --- | --- | --- | --- | --- | --- |
| `p50` | **0** | **0** | **0** | **0** | **0** |
| `p90` | 1.153 | 1.254 | 1.311 | 1.367 | 1.401 |
| `p95` | ~1.50 | | | | ~1.59 |
| `p99` | ~1.74 | | | | ~1.80 |

**`p50 ≡ 0` 是硬结论**：字符框内过半像素是背景，中位数恒为 0。
→ **任何 `p50 × 系数` 的下界恒为 0，是死路。**

`_FT_` 与 `_RT_` 两类图的 `p90` 同量级（1.25~1.40），刻印亮度无本质差别。

复现：
```
build\Release\markloc_p90stat.exe "release_defectview\model\v00" "image\ok"
```

### 3.3 误报机理（0109_RT）

| 环节 | 数据 |
| --- | --- |
| 模型笔画覆盖不住真实笔画 | `0109_RT` 字符区内「信号亮、模型认为空白」占 **40.1%**；干净图 `0001_FT` 仅 **9.4%** |
| 覆盖缺口随核放宽收窄 | `dilateK=9` → 40.1%，`dilateK=41` → **6.2%** |
| 命中框内信号强度 | 峰值 1.76~1.97，是 `strokeHi=0.35` 的 **5.0~5.6 倍**（确实是墨） |
| 模型在同一处的判断 | 墨迹占比仅 **4% / 5% / 7%**（模型认为该处空白） |
| 成条 | `bridge=25` 把相邻笔画连成跨 4 字符的亮带 |
| 得分 | `composite = 484 × 4 = 1938` → 确定级 |

**方向判据**：真划痕应是「模型有墨 → 信号空白」；0109 是「模型空白 → 信号有墨」。
→ **`0109_RT` 是误报**（用户已裁定）。

### 3.4 高漏出率不是充分条件

84 张 ok 中，字符区漏出率 > 25% 的共 **21 张，全部是 `_RT_`**，`_FT_` 一张都没有。但其中 **19 张仍判 OK**。

→ 漏出率高是**必要不充分**条件。真正决定的是漏出的地方**是否恰好连成跨界长条**。

### 3.5 已排除的怀疑

| 怀疑 | 实测 | 结论 |
| --- | --- | --- |
| 全局相位对齐出错 | 关掉后命中从 9 条涨到 **28 条** | 不是，全局对齐在帮忙 |
| 逐字符对齐出错 | `boxdiag` 22 框平均召回 **0.999**（对齐后）vs 0.860（不对齐），无框 < 0.85 | 不是 |
| 门槛设太松 | 提到 1500 时 2224/2287/2426 贴线 | 不是，会引入漏检 |

## 四、已确认的决策（2026-10-22 一轮问答）

| # | 决策 | 内容 | 依据 |
| --- | --- | --- | --- |
| D1 | 验收口径 | **由用户实测决定**，目录和文件名为参考，不作准绳 | 用户原话 |
| D2 | `0109_RT` | **是误报** | 3.3 方向判据 |
| D3 | 修法 | **重训模型**（非扩掩膜、非提门槛） | 3.3 |
| D4 | 重训范围 | **只重跑 `chardet::train`**，重新生成 `freq.png` / `ref.png`；模板库不动 | 问题只在 `freq.png` 链路 |
| D5 | 自适应阈值 | 阈值 = **每张图字符框内的 `p90`**；下界 = `p99 × 0.5`；上界 = **1.50** | 3.2 |
| D6 | 训练/推理拆开 | 训练用每图 `p90` 二值化；写回 `model.json` 的 `strokeHi` **保持 0.35 不变**，推理侧零改动 | 一次只改一个变量 |
| D7 | 模型落位 | 原地覆盖 `release_defectview\model\v00`，旧版备份到 `v00\versions\<时间戳>\` | 沿用现有版本机制 |
| D8 | 交付材料 | 全量 CSV + 前后对比表 + 热点图，三样都给 | 用户要自己复核 |

### D5 的数值校验

| 量 | 实测 | 对 `p90` 的约束 |
| --- | --- | --- |
| 阈值 `p90` | 1.153 ~ 1.401 | — |
| 下界 `p99 × 0.5` | 0.87 ~ 0.90 | **低于** `p90` 下限 1.153 → 正常图不触发 ✓ |
| 上界 `1.50` | 1.50 | **高于** `p90` 上限 1.401 → 正常图不触发 ✓ |

两个边界在正常图上都不触发，只在异常图上兜底。**这是保底该有的样子。**

## 七、踩过的坑（勿重犯）

| 坑 | 教训 |
| --- | --- |
| 用 PowerShell `Get-Content -Raw \| -replace \| WriteAllText` 改 `CMakeLists.txt` | 中文注释被毁成 GBK 乱码。**永远不要用文本 cmdlet 往返这个文件** |
| 维护 `out\oklist.txt` 当工具输入 | 中文文件名被写成 `(??)`，42 张 `_FT_` 图静默丢失。**工具直接遍历目录** |
| 用 PowerShell 按空白切分解析含 `[...]` 的文件名 | 下标全错。**让工具输出 TAB 分隔，或用工具自己算** |
| 目录遍历不筛视角 | `image\ok` 含 `_00.._05` 六个视角，84×6=504 张混入统计。**必须只取 `_00`** |
| 按钮宽度做像素取色判断 | 圆角 + DPI 导致误报，实际 `truncated=0` |
| 分数表空表通过自检 | 旧检查只断言 `columnCount >= 8`，0 行也满足 |
